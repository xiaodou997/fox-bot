## 3. 授权和前置检查

- [ ] 已确认测试范围与账号授权，真实发送仅到指定测试会话。
- [ ] 已确认暂停/紧急停止和人工接管入口可用。
- [ ] 不存在第二个未受控自动发送端。
- [ ] 记录初始权限、账号、草稿、通知动作与窗口状态。
- [ ] 确认没有真实密钥或个人聊天数据进入公开日志/录像。
- [ ] 只读测试明确关闭发送；需要发送时明确启用测试范围。

不适用的项目写明原因，不能直接勾选。例如 G0 文档检查不涉及聊天账号和设备控制。

## 7. 未覆盖、阻塞与风险

写明没有测试的系统、应用版本、语言、主题、群聊、锁屏、通知通道、恢复和持续场景，以及已知失败。没有执行的软件测试不因文档完整而变成通过。

## 8. 结论与矩阵更新

明确本回执能证明的能力，例如“某提交在某应用版本的当前私聊窗口完成 GUI 自动发送与结果观察”。不要只写“全部正常”。

如有硬门禁失败，对应能力保持关闭。更新矩阵时填写回执路径、适配器、环境、模式及限制；未验收组合仍为 PLANNED 或 IMPLEMENTED / NOT_RUN。

## 9. 清理与证据保存

- [ ] 退出测试自动模式并核实执行进程状态，未完成动作已记录。
- [ ] UNKNOWN/待对账任务没有被当作垃圾清理或在下次启动重复发送。
- [ ] 恢复用户配置时未覆盖测试期间用户新产生的草稿/剪贴板。
- [ ] 测试数据和截图按保留策略删除或脱敏保存。
- [ ] 回执使用稳定的相对链接或受控证据位置；公开仓库没有敏感附件。

不要仅凭 IPC 不可达就假定执行进程已退出；不要为了清理而删除仍可能被活进程使用的状态。
