## 3. 关键新增场景

**协议与业务边界（AI-01、AI-03、AI-04）：** BusinessV1 不加入角色或模型字段；Chat Completions 支持显式 Generic 提示词，也支持 Custom 知识库服务完全不加 system 消息。保留发言人/未解析内容元数据；reply/no_reply/handoff 分开处理。半截 JSON、SSE、length/tool_calls/refusal、错请求或额外路由字段不会进入待发送状态。

**HTTP 取消与幂等（AI-05、AI-07、CORE-06）：** 请求发送前、发送过程中、成功返回后但未接受时取消；等待并发槽位时取消；单次/总超时；有界重试；Retry-After 不被缩短。模拟服务已生成而响应丢失时，两次请求体和幂等键完全相同，只产生一次逻辑生成。未声明幂等的服务只尝试一次。401 不重试，错误不回显正文、认证值或端点。

**历史与回执（AI-02、AI-06、TX-06、TX-07）：** service_managed 仅发当前增量；最终回执确认前阻止下一轮；UNKNOWN 不提交已发送历史。最终 revision2 不被晚到 UNKNOWN revision1 覆盖。取消 tombstone 即使先于生成到达也有效。回执 503、丢失 ACK、ACK 已到但未保存、进程重启等只重传回执，不再次调用模拟聊天发送。错误 ACK 和重试耗尽进入 SUSPENDED。

**进程中断：** HTTP CLI 在本机 fixture 确认已收到生成请求后被实际终止，测试等待其退出后打开同一状态目录，恢复 GENERATING→ERROR 并补传取消回执；没有形成聊天发件箱动作。不是仅手动更新一列状态。其他恢复场景还通过 Runtime 关闭/重开覆盖持久化断点，不把所有测试都称为杀进程。

**配置、网络与迁移：** 明文非 loopback、URL 凭据/query/fragment、不同源反馈地址被拒绝；重定向不转发 token 或消息；长度与 chunked 响应均有上限。旧凭据配置不能认领/发送另一配置的回执；仅改变超时/并发仍可补偿原回执。schema1→2 增量升级保留消息，G1a 原有外来/未知数据库拒绝测试继续通过。

## 4. 独立 HTTP smoke 的实际输出

```json
{
  "loopback_only": true,
  "synthetic_data_only": true,
  "first_run": [1, 1],
  "replay": [0, 0],
  "compensation_mock_send_calls": 0,
  "feedback_acked": 2,
  "generate_requests": 2,
  "feedback_requests": 3
}
```

first_run/replay 的二元值分别是生成作业和模拟发送次数。共两个独立合成场景：正常场景一条；补偿场景一条，回执先返回 503，再由独立 feedback 命令成功补传。因此两次生成、三次回执请求，不表示客户消息发送了三次。

脚本自行创建临时配置、状态目录和随机 127.0.0.1 端口；不使用示例中的固定 8787 服务。脚本退出前关闭服务器并等待线程；子进程使用有界 timeout，测试清理前等待子进程退出。没有留下需要用户手动停止的本轮测试服务。

## 5. 复核中修正的设计细节

传输协议与提示词策略分离，避免“兼容接口”强加 system prompt。语义配置指纹不包含运行超时、并发等操作参数，避免仅调超时就无法补偿旧回执。回执 claim 绑定服务配置，发送前检查，不能先发送到错误端点再于 ACK 阶段拒绝。上述均有针对性回归测试。

所有认证测试只使用明确的 synthetic 测试 token。代码/示例/日志未引入真实聊天、真实 API key 或第三方模型权重；没有运行专用全仓秘密扫描器，不把人工源码复核等同于安全审计。
