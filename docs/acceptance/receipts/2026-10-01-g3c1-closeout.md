## 1. 原超时位置已定位，不再猜测截图或数据库

对原 UNKNOWN 任务 `742961` 进行有界复现，采样栈停在 `g3c_real::send_once → security_framework::passwords::generic_password → SecItemCopyMatching → SecKeychainItemCopyContent`，尚未进入 native 读取器。采样后结束该进程，没有任何再次发送；旧回执哈希保持不变。

修复对现有文件型 Keychain 调用禁用隐式授权 UI，并用进程内互斥保护该全局设置；只在原来允许 UI 时建立恢复 guard。它不修改钥匙串 ACL，不读取其它服务的密钥，不改用明文，也不将访问被拒绝当成密钥缺失后覆盖旧 key。增加 `credential-check NAME --allow-keychain-read` 与固定阶段耗时日志，输出不含凭据或聊天正文。

真实结果：

| 操作 | 结果 | 总耗时 |
| --- | --- | --- |
| 检查旧 key | ACCESS_DENIED，OSStatus=-25293 | 0.023 秒 |
| 原任务只读核对入口 | CREDENTIAL_READ 明确失败，退出码 1；未启动 native worker | 0.021 秒 |
| 新测试 key 正常读取 | 成功，CREDENTIAL_READ 阶段 15ms | 见实际发送记录 |

本机证据：`target/g2d-real/g2d-test/g3c-1/742961/timeout-diagnosis.json` 与 `noninteractive-keychain-final-report.json`。原 90 秒无结果的处理问题已消除；**没有宣称旧凭据授权已恢复**。旧账本仍需原授权才能读取，不能通过重建密钥解密。

Apple 对 `errSecAuthFailed` 的定义是授权或认证失败；`errSecInteractionNotAllowed` 为另一类错误。本次实测是前者，因此保留 ACCESS_DENIED 与 AUTHORIZATION_REQUIRED 的区分。依据：`https://developer.apple.com/documentation/security/errsecauthfailed`、`https://developer.apple.com/documentation/security/errsecinteractionnotallowed`。开发构建签名变化可能影响旧凭据访问，但本轮没有把具体 ACL 变化推断成已验证事实。

## 2. 保留一次未发送的失败，不把换测试当作重发

最先建立独立任务 `853207`：回填一次，原生返回 DRAFT_MISMATCH，send_requests=0，未形成 send 前回执。随后只读确认正文正好是 `FoxBot G3c1 853207`，消息数不变，但历史消息哈希在连续读取间波动。旧错误将 surface/context 与正文不符混在一起，误导了故障名称。

修复沿用 G2 已有的历史上下文规则：折叠水平空白、统一换行、忽略汉字与 ASCII 字母数字边界的单个空格；增加独立 `continuity_digest`。**待发正文和新增己方消息仍使用原始文本 digest 精确匹配**，不修复数字、大小写、标点或词义。真正的新消息、顺序变化和内容变化仍会触发上下文变化。原生错误也拆开为 TARGET_CHANGED 与 DRAFT_MISMATCH。

采集协议因此升级为 `foxbot.native-send-worker.v3` / `WECHAT_RECEIPT_V3`。不同版本的历史回执不静默改写。修复版三次只读观察：消息数均 10，不完整条目均 0，raw_signatures_stable=false 而 context_signatures_stable=true。

为进行独立的新版本验收，仅清理本轮自己写入且确认未发送的精确测试草稿。首次全选/删除后检查未清空；重新观察确认只剩本测试的 17 字符前缀后，执行有界删除并确认空输入框。没有覆盖其它正文、执行发送或重试旧 action。记录在 `853207/first-execution-report.json` 与 `853207/owned-draft-cleanup.json`；此任务的 UNKNOWN 不改成 PASS。诊断时进行过一次窗口截图核对，截图没有进入仓库。
