# FoxBot 验收清单

- 编号：FB-ACCEPTANCE-001
- 日期：2026-10-01
- 关联：[设计基线](../design/BASELINE.md) · [适配矩阵](../adapters/CAPABILITY_MATRIX.md) · [回执模板](RECEIPT_TEMPLATE.md)

**本文是测试规范，不是执行报告。除独立回执明确记录通过证据外，所有案例视为 NOT_RUN。当前 macOS 微信已有 G2 读取、G3c-1 固定短回复和 G3c-2 单条真实 AI 回复回执；G3c-3 多行/较长回复在独立真机回执产生前仍是 NOT_RUN。模拟核心的覆盖范围见独立回执，不能据本清单本身声称软件测试通过。**

## 1. 使用方法与测试边界

先固定 FoxBot 完整提交 SHA、构建包摘要、平台/设备、目标应用版本、语言/主题/字体/缩放、聊天类型、模式、通道和账号绑定。复制回执模板，填写本次覆盖的适配器、案例和未覆盖范围。

测试优先使用模拟窗口、合成消息和脱敏 UI 树。真实发送只允许使用明确授权的测试账号与测试会话；执行前检查允许列表、退出开关和接管入口，使用容易辨认的测试消息编号。不能默认向真实联系人、工作群或未知通知动作发消息。只读探针不得顺带启用发送。

每个案例记录：前置条件、操作、预期、实际、证据和 PASS/FAIL/BLOCKED/NOT_RUN/NA。截图、日志与接口录制先脱敏；密钥和通知动作凭据不进入回执。

硬门禁案例出现串会话、未授权发送、覆盖用户草稿、未知状态重发、凭据泄露时，停止对应自动能力并记录失败，不用其他成功次数抵消。NA 必须说明为何不适用，不能用来跳过某通道必需的发送验证。

当前采用[无人值守独占执行契约](../development/G3B_UNATTENDED_EXECUTION.md)：自动执行期间不人工操作目标聊天界面。人机并发编辑、IME 组合态和键鼠静默证明不再是发布门禁；开发交接使用现有 pause/stop/resume。残留草稿、写入完整性、身份、暂停和防重复发送仍必须测试。

| G2 平台探针 | 适配器对应 AD/MC/WI、实际需要的 OC；只读模式 | 指定环境的已观察能力；不能声明自动发送。 |
| G3 当前会话 | G1 回归＋对应平台＋TX 全链路＋需要的 GR/OC | 指定组合的当前会话自动收发。 |
| G4 多会话 | G3＋NW-01～NW-05 | 指定范围的多会话值守；不能推导成所有后台消息可达。 |
| G5 候选发布 | 对应模式的 G3/G4＋RL-01～RL-05 | 已列明环境、模式和限制下的候选发布验收。 |

代码可以在能力默认关闭、状态准确的前提下合入，但发布门禁不能由编译通过替代。当前会话和多会话、私聊和群聊、GUI 和通知通道分别判定。

## 4. G1：公共核心与会话隔离

| ID | 操作 | 预期 / 证据 |
| --- | --- | --- |
| CORE-01 | 在两个账号、两个同名联系人和两个窗口中注入消息，再切换登录账号。 | 任务和服务端会话分别绑定；身份变化使旧任务失效，标题相同不合并。 |
| CORE-02 | 启动时提供历史消息；暂停/重启后重复提供同一窗口；再加入一条新消息。 | 历史只建上下文，不补发；新消息按规则触发；恢复不重放全部历史。 |
| CORE-03 | 同一消息依次从通知、UI 树、OCR 多帧到达，并注入通知更新/撤销。 | 合并为同一逻辑事件或标记歧义；不能因来源增多多发；更新不一律视为新消息。 |
| CORE-04 | 连续注入两个真实独立的“好的”，再重放第一条的观察结果。 | 两条独立消息保留；重放观察不增加第三条；不能全局按文本哈希去重。 |
| CORE-05 | 连发多条短消息，持续超过合并窗口；观察队列。 | 有合并上限和最大等待，不无限推迟；同会话有序，队列有背压。 |
| CORE-06 | 生成期间收到新消息、切换会话/配置；取消请求后再返回旧响应。 | 旧 request/revision/config 不匹配结果不可写入；取消不假定服务端已停止。 |
| CORE-07 | 两个会话同时就绪，启动两个本地执行进程争抢 GUI 任务。 | 模型可并发但 GUI 执行串行；本地唯一执行权有效；丢锁任务停止，不能双发。 |
| CORE-08 | 记录任务各持久化阶段，分别在事务前后崩溃并重启。 | PREPARED 可按策略恢复；EXECUTING 之后先对账；UNKNOWN 不直接回到可发送状态。 |

## 5. G1/G3：回复服务

| ID | 操作 | 预期 / 证据 |
| --- | --- | --- |
| AI-01 | 对通用模型和定制服务分别录制脱敏出站请求。 | 通用模式按配置组装；定制模式不强加角色/知识库/Jev，目标和凭据不被回复修改。 |
| AI-02 | 分别测试 client_managed/service_managed，上下文重复、同名会话及服务配置切换。 | 全量和增量契约明确；不重复追加历史；账号、机器人、服务端会话隔离。 |
| AI-03 | 服务返回 reply、no_reply、handoff，及只返回字符串的兼容接口。 | 只有合法 reply 进入发件箱；其余按状态处理；不额外调用意图模型。 |
| AI-04 | 返回流式半截、取消后续片段、畸形 JSON、错误关联 ID、空文本和超长输出。 | 不发送半截或错误目标结果；不过度修复业务文字，错误状态可解释。 |
| AI-05 | 有状态服务在请求已接受后超时，模拟支持/不支持幂等键的两种实现。 | 支持者按协议对账；不支持者不假定重试安全；取消与历史修正策略有证据。 |
| AI-06 | 生成完成后取消发送、发送结果未知、发送成功但回执上传失败。 | 不把未发送候选记为已告知客户；回执重试不重发消息；服务端历史可对账或暴露限制。 |
| AI-07 | 聊天文字中加入更换联系人/上传全部历史/修改接口的指令，模拟 401、429、断网。 | 内容不能改变本地权限和路由；有限重试，不擅自切换服务商，不输出含密钥的错误。 |

| TX-04 | 模拟写入返回成功但未生效/只写一半；对实际写入通道测试中文、英文、多行和支持的表情。 | 内容读回匹配后才可发送；不因 API 成功直接发送，不增加人工剪贴板竞争测试。 |

| TX-07 | 通道返回已接受但界面未出现消息、出现相同旧气泡、出现失败图标、仅有己方新气泡。 | 证据等级和动作关联正确；不把旧气泡当新回执，不把己方输出写成送达/已读。 |
| TX-08 | 自己发出的消息被再次采集；两个测试机器人互回；连续失败后恢复。 | 不回复自身输出；频率/连续回复/预算上限和熔断生效；恢复不刷屏。 |

## 8. OCR 与采集一致性

| ID | 操作 | 预期 / 证据 |
| --- | --- | --- |
| OC-01 | 使用固定数据集测试中文/英文/繁体、短句、单字、数字、金额、小数点、型号、手机号和否定词。 | 记录字符错误率及关键字段完整匹配率；不做未经标注的语义纠错，保存样本/模型版本。 |

| OC-03 | 树读取与截图之间滚动，改变窗口原点、分屏、缩放或显示器。 | 检测到快照/布局不一致；不把旧矩形裁到新消息，也不使用上一会话的缓存。 |
| OC-04 | 对局部遮挡、截断气泡、受保护画面、空帧、低质量帧和未知置信运行。 | 保留不可读/不完整状态；不拿旧文本填空，不绕过保护；不能默认全当对方。 |
| OC-05 | 无界面变化、快速变化、OCR 长时间忙、最小化、暂停与恢复。 | 有限采集、背压、过期帧丢弃、重新同步；无无限队列和持续无效 OCR。 |
| OC-06 | 比较系统 OCR/轻量候选，测首次加载和稳定运行、空闲及持续变化。 | 记录端到端 P50/P95、峰值内存、CPU、移动耗电/温升、包体；模型大小不是内存，未测不填估计值。 |

数据集不得只保留“容易识别的正常消息”。训练/调参样本与最终保留测试集分开；记录样本数量和失败样本。数值阈值先在 G2 基于目标环境登记，G5 前固定，不能看到结果后降低门槛。

| RL-04 | 检查本地存储、日志、崩溃报告、模型请求、截图与诊断导出；模拟系统凭据库不可用。 | 默认不传截图、无密钥/原文泄露；保留与清除策略有效；凭据失败不降级明文。 |
| RL-05 | 核对复用源码/依赖/模型/字典的来源、许可证、摘要、版本锁和更新回退。 | 上游通知保留，权重与代码许可分开核对；不下载执行未验证资源；应用更新触发受影响回归。 |

发布前必须列出明确的延迟、内存、队列、耗电/温升等预算和适用硬件；尚未登记预算时 RL-02 只能作基准采样，不能给出性能门禁 PASS。4 小时是拟定最低持续验收窗口，不是任何现有测试结果；更高时长按产品使用目标追加。
