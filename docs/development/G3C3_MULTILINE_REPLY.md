# G3c-3：多行与较长纯文本回复

- 日期：2026-10-03
- 基线：[G3c-2 真实 AI 回复](G3C2_REAL_REPLY.md)已在绑定测试私聊完成单条短回复闭环。
- 当前状态：**IMPLEMENTED / OFFLINE PASS；真实微信多行回复验收待执行。** 固定提交和门禁见[实现回执](../acceptance/receipts/2026-10-03-g3c3-multiline-readiness.md)。
- 范围：macOS 微信、已绑定当前私聊、单条真实 incoming、单条纯文本回复。持续值守、多会话、附件和富文本不属于本增量。

## 1. 支持范围

本增量将原来的“单行、最多 80 个 UTF-16 单元”扩展为：

```text
最多 512 个 UTF-16 单元
最多 12 行
允许 LF 换行
不允许 CR、Tab 或其他控制字符
不允许首尾空白或末尾光标形态的竖线
```

超过范围时仍然是 `UNSUPPORTED_REPLY_NO_WRITE`：保留模型完整结果，不截断、不自动改写、不进入微信输入区。正常回复上限仍由 Runtime 的 `max_reply_chars` 与原生写入策略共同约束，任一侧不接受都不能发送。

普通模型的新默认提示词允许在需要时分段或换行，并建议控制在 300 个汉字以内；这只是生成偏好，不是安全边界。自定义 BusinessV1 服务继续使用服务自身规则。已经保存的用户提示词不会被版本升级静默覆盖。

## 2. 两条写入路径

短单行且不超过 80 个 UTF-16 单元时，继续使用已有 Unicode 事件包：

```text
点击当前输入区
→ 分字符、分包注入 Unicode
→ OCR 按期望正文核对
```

多行或较长回复使用受控剪贴板路径：

```text
内存快照当前通用剪贴板（有界）
→ 临时写入待发正文
→ Cmd+V 粘贴到已核对的输入区
→ Cmd+A / Cmd+C 复制输入框完整正文
→ 与模型原文逐字符核对
→ 恢复原剪贴板的所有已捕获类型
```

剪贴板快照最多 8 MiB、32 个 item、每个 item 最多 64 个类型。任一类型无法完整读取、写入或恢复时，本次原生动作失败关闭；不会在无法保存原剪贴板时先粘贴回复。该流程不要求用户参与，也不是人机同时编辑兼容功能。

多行输入不模拟 Return/Enter，因此不会把换行误当发送动作。发送仍然只点击当前截图中唯一识别到的“发送”按钮。

## 3. 完整正文与上下文门禁

OCR 只用于短回复和消息区证据；多行/长回复的输入框正文使用复制回读，统一 CRLF/CR 为 LF 后与期望正文精确比较。正文中的数字、大小写、标点、空格、换行和文字变化都不能自动修复。

输入区变高时，可见聊天区可能只保留原历史的后缀。本轮允许的唯一上下文变化是：**旧消息只能从顶部被遮住，底部不能新增、删除、改序或改内容。** 写入前、写入后和发送前都保留至少两条连续上下文锚点；出现新消息或目标变化时停止，不继续发送旧回答。

发送后输入区收起，聊天区可能重新露出更早的历史行。回执匹配因此允许新截图在连续锚点之前多出旧历史，但连续锚点之后必须恰好新增一个对应的己方消息。

## 4. 回执 V4 与兼容性

原生 IPC 升级为：

```text
foxbot.native-send-worker.v5
WECHAT_RECEIPT_V4
```

V4 在原始正文 digest 和 continuity digest 之外增加 `content_digest`。它只在多行/较长回复的**发送后视觉回执**中使用：移除布局产生的空白和换行，再比较所有非空白字符。发送前已经通过复制回读验证完整原文，因此这一投影只处理微信气泡自动换行，不能允许非空白字符变化。

历史 V3 回执继续解码和按原精确正文规则核对；不会补造 `content_digest`、重写旧 receipt 或把旧 UNKNOWN 提升为成功。未知 revision 仍然拒绝。

## 5. `fill_uncertain` 恢复

既有受限恢复入口也支持本轮范围。它仍然要求：

- 同一个 action 处于 `UNKNOWN / fill_uncertain`；
- 没有发送前 receipt，说明 send 尚未开始；
- action 未超过 30 分钟；
- 当前账号、会话、窗口和唯一新增 incoming 与原任务一致；
- 输入框完整正文复制回读后与账本回复精确一致。

恢复只发送已经存在的草稿，不再次调用模型，也不再次 fill。一般 UNKNOWN、已有 receipt、正文不一致或上下文变化不能使用该入口。

## 6. 测试与验收

离线回归新增覆盖：

- 300 字长回复和两段多行回复不截断；
- 超过 512 UTF-16、超过 12 行、Tab、CR/CRLF 均零写入；
- 剪贴板文本和自定义类型完整恢复，超出快照预算时拒绝；
- 输入区变高只允许顶部历史被遮住；
- 发送后露出旧历史仍可关联唯一新增己方气泡；
- 气泡视觉换行可用 V4 content digest，任一非空白字符变化不能通过；
- 多行既有草稿恢复不重新 fill；
- V3 精确回执兼容，未知 revision 拒绝。

完整门禁命令：

```bash
python3 scripts/g1_integration_check.py --with-macos-probe
```

真实验收必须使用新的 RUN 和新的测试 incoming，验证真实模型产生两段或较长回复后：回填一次、发送一次、`VERIFIED_OUTGOING`，同 RUN 重放模型和原生调用均为 0。离线 worker、Swift 策略测试和此前短回复 PASS 都不能替代这次真机验收。

真实验收通过后，下一阶段进入当前绑定私聊的持续值守：轮询新消息、逐条建立任务、处理等待/失败/暂停和连续消息，但不在本增量提前开放多会话自动导航。
