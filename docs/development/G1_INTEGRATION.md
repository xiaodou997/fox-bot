## 1. 可重复执行的集成入口

```bash
python3 scripts/g1_integration_check.py --with-macos-probe
```

默认不带参数也可运行 G1 检查；macOS 参数追加 Swift 构建/合成树测试，不自动读取真实聊天。脚本使用现有 cargo（找不到时使用 HOME/.cargo/bin/cargo）和 Python 标准库，不安装工具链。检查依次为 Rustfmt、Clippy、全工作区测试、关闭加密 feature 的定向测试、host/http 构建、两组 loopback smoke、Python 运行器测试、文档和空白检查，以及可选 Swift 测试。

每步有独立日志与实际退出码，失败即停止，不自动重跑直到变绿。日志和 JSON 报告在 `target/g1-integration/<随机编号>/`，由 Git 忽略。报告记录 HEAD 和检查前后全部未忽略文件的内容指纹；源文件改变时，即使命令返回成功也不给集成 PASS。它不联网检查 Markdown 外链、不测试真实模型、不写 Keychain、不读真实应用。crate 依赖首次获取仍可能访问已配置包源。

报告中的耗时是该次检查耗时，不是性能门槛或长稳时长。脚本只声明本地检查集合通过，不能把“检查项数量”当 Rust 测试数，也不能把合成测试视为原生兼容。

测试步骤还解析实际执行数量并设置最低要求：Rust工作区至少118项、关闭加密功能的精确过滤至少1项、Python至少49项、Swift XCTest至少71项（包含 G2c 身份、worker host 和 ground-truth 测试）。只有退出码0但没有执行证明的步骤也判失败；Swift按独立 .xctest bundle 汇总，不重复计外层套件，也不漏计第二个 bundle。最低数量随明确的测试范围变更维护，不根据失败临时降低。

## 2. 本轮发现并修复的调度边界

原宿主 select 中，定时 tick 可以先于已经进入 input 队列的新消息执行。当旧回复已经 READY 时，可能先发旧候选，再处理新消息或人工输出。停止信号在进入 tick 后也缺少局部复核。

三个确定性回归分别在 tick 之前排入新消息、排入己方人工输出，以及在 tick 边界设置 stop。本轮接续已有未提交的修正和测试，重新审阅并执行回归；实际结果见独立回执，不把接手前未经本轮核对的失败次数写成执行证据。

修正为：tick 首先检查停止/控制消息；在发送决策之前有界处理最多64条已排队观察，触发既有版本失效/取消；队列仍未清空或控制待处理时，本轮不派发。多会话循环中再次检查待处理输入/控制。这样既不越过已经接收的输入，也不靠无限排空隐藏暂停或停止。

这不是任意第三方 GUI 的原子事务。检查之后仍可能发生新的系统输入，未来原生适配器仍必须在写入和发送前复核目标、正文、布局与人工接管；当前同步 MockChannel 的可中断性不外推为原生保证。对应 CORE-06、TX-01、TX-08、NW-03 的合成子集，不能把完整案例标 PASS。

## 4. 下一阶段的具体边界

G2a/G2b 仍是只读感知；[G2c](G2C_IDENTITY_HOST.md) 已增加显式会话 Binding、应用运行会话失效、跨帧连续性、ground-truth 门禁和 Rust worker 生命周期。真实微信 host 探针仍固定报告 PROVISIONAL，因为没有真实标注接受记录和配置 Binding。运行中 QQ、真实 Observation 联调和账号应用内重登录自动探测仍待关闭。

只有得到真实账号/会话、消息顺序/方向、草稿和目标新鲜度证据后，才设计映射到核心 Observation 的桥接。最终真实发送仍必须单独进入 G3 专用测试会话验收；G1管理与存储缺口在允许持久化真实消息前关闭。
